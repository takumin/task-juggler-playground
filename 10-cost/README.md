# 10. コスト

工数だけでなく金額を扱う。リソース単価から人件費を積み上げ、
固定費と売上を加えて収支を出す。

## 実行

```sh
bundle exec tj3 -o 10-cost/out 10-cost/cost.tjp
```

生成物: `out/01-balance.html`、`out/02-task-cost.html`、`out/03-resource-cost.html`

## 学ぶ内容

- `account` — 勘定科目の定義 (入れ子可)
- `aggregate` — その科目が何に由来する金額を集めるか
- `rate` — リソースの日額単価
- `chargeset` — どの科目に付けるか (按分も可能)
- `charge` — 一時費用・継続費用
- `balance` — 収支分析の対象指定
- `currency` / `currencyformat`

## 実行結果

### 収支サマリー

| 科目 | 金額 |
|---|---|
| 費用 | 1,971,429 |
| ├ 人件費 | 1,000,000 |
| ├ 外注費 | 500,000 |
| └ 諸経費 | 471,429 |
| 収益 | 8,000,000 |
| └ 検収入金 | 8,000,000 |
| **収支** | **6,028,571** |

### タスク別のコスト

| タスク | 工数 | 費用 | 収益 |
|---|---|---|---|
| 設計 | 5.0 | 250,000 | 0 |
| 実装 | 20.0 | 1,250,000 | 0 |
| 納品・検収 | 0.0 | 0 | 8,000,000 |

設計の 250,000 は「5 人日 × Alice の日額 50,000」。
リソースの `rate` が、そのタスクの原価として積み上がっている。

## aggregate — この段階の核心

`account` の `aggregate` は「**何に由来する金額を集める科目か**」の宣言。

| 値 | 集める対象 |
|---|---|
| `tasks` (既定) | タスクの `chargeset` 経由の金額 |
| `resources` | リソースの `chargeset` 経由の金額 |

**タスク側に `chargeset` を付ければ、リソースの `rate` 由来の人件費も
そのタスクのコストとして計上される。** タスク別原価を見たいならこの形にする。

リソースの `chargeset` に `aggregate tasks` の科目を指定すると
`cannot aggregate amounts related to resources` エラーになる。

## charge のタイミング

| 指定 | 意味 |
|---|---|
| `onstart` | 開始時に一括 |
| `onend` | 終了時に一括 |
| `perhour` / `perday` / `perweek` | 期間に比例 |

どの科目に付くかはタスクの `chargeset` で決まる。

## 気をつけるポイント

- **`cost` / `revenue` 列を使うには `balance` の定義が必須**。
  ないとセルが `No 'balance' defined!` になる
- 金額を計上できるのは**末端 (leaf) の科目だけ**
- `chargeset` で按分する科目は、**同じトップレベル科目の配下**でなければならない。
  合計は必ず 100% (省略した科目には残りが均等配分される)
- 通貨・数値の既定書式はヨーロッパ式 (`1.234.567,89`)。日本式にするなら
  `currencyformat "-" "" "," "." 0`
- `accountreport` は「未テスト」警告つきの機能
- `project` ヘッダの日付は UTC 基準 (06 と同じ落とし穴)。
  この教材も開始を `2026-08-01` に広げて回避している

## 得られるもの

工数計画がそのまま原価計算につながる。
「この機能を作るのにいくらかかるか」「この案件は黒字か」を、
別途スプレッドシートを作らずに計画データから直接出せるようになる。
