# 02. 構造

タスクをツリーに組み、依存関係を正しく張る。TaskJuggler で最初につまずくのは
たいてい依存の参照記法なので、ここを固めておく。

## レポートの内容

| ファイル | 内容 |
|---|---|
| `structure.html` | ガントチャート |
| `workload.html` | リソース別の負荷 |

## 学ぶ内容

- `task` の入れ子による**コンテナタスク**
- 依存関係の3つの参照記法
- コンテナに `depends` したときの意味
- `milestone` (期間ゼロの時点)
- `gapduration` と `gaplength` による依存の間隔
- `resourcereport` でリソース視点に切り替える

## 依存の参照記法

| 記法 | 意味 |
|---|---|
| `!interview` | `!` 1つで**親を起点**。つまり兄弟タスクを指す |
| `!!spec.doc` | `!!` で2階層上を起点にパス解決 |
| `spec` | 起点記号なしは**ルートからの絶対パス** |

コンテナを `depends` に指定すると「**その配下が全部終わってから**」の意味になる。

## 実行結果

```
要件定義    2026-08-03 → 08-12  Effort 8.0   ← 3.0 + 5.0 の集計
  ヒアリング  2026-08-03 → 08-05  Effort 3.0
  仕様書作成  2026-08-06 → 08-12  Effort 5.0
開発        2026-08-13 → 08-26  Effort 18.0
  API 実装   2026-08-13 → 08-26  Effort 10.0
  UI 実装    2026-08-13 → 08-24  Effort 8.0
テスト       2026-08-31 → 09-04  Effort 5.0
リリース     2026-09-04           ← milestone
```

コンテナ「要件定義」は自分で工数を持たず、期間は子の範囲、工数は子の合計になる。
「開発」が 08-13 始まりなのは、`depends spec` が「要件定義の配下すべての完了」を
待つため。

## gapduration と gaplength

依存元の完了 `2026-08-26 18:00` を起点に、同じ `5d` でも結果が変わる (実測)。

| 指定 | テスト開始日 | 理由 |
|---|---|---|
| `gapduration 5d` | 2026-09-01 | 暦時間。土日も消費して進む |
| `gaplength 5d` | 2026-09-03 | 稼働時間。土日を数えないので後ろにずれる |

01 で見た `duration` と `length` の対比が、依存の間隔にもそのまま出てくる。

## 気をつけるポイント

- **コンテナタスクに `effort` は書けない**。子が期間を決める
- `!` の数は「何階層上を起点にするか」であって「何個上の兄弟か」ではない
- `milestone` は `task` の**属性**。`effort` / `duration` とは併用できない
- 依存先のタスクは**定義済みでなくてもよい** (前方参照できる) が、
  ID を間違えるとエラーになる。パスは常にツリー構造を意識して書く

## 得られるもの

実プロジェクトの WBS をそのまま tjp のツリーに落とせるようになる。
依存の参照記法は 08 の論理式フィルタでも同じ考え方で使うので、
ここで身につけておくと後半が読みやすい。
